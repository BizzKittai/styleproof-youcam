# StyleProof

[Open recorded demo](https://bizzkittai.github.io/styleproof-youcam/)

No login, installation or API key is needed. This read-only viewer shows two
saved, genuine YouCam Clothes V4 results. Viewing or switching looks creates no
new generation request.

Compare two real YouCam clothing results with their source images, recorded
processing evidence and unit consumption.

StyleProof is a hackathon prototype by BizzKitt BV. It compares a forest-green
crewneck and a rust shirt on the same original synthetic adult model. The
viewer shows saved, genuine YouCam Clothes V4 outputs. It does **not** submit a
new provider request when someone views, switches or resets the comparison.

Repository: https://github.com/BizzKittai/styleproof-youcam

## Run the local demo

Use Node.js 24 (validated with 24.19.0). No package installation is required.

```sh
git clone https://github.com/BizzKittai/styleproof-youcam.git
cd styleproof-youcam
node tools/serve-demo.mjs
```

Open http://127.0.0.1:4178 in a browser. The recorded comparison needs no API key,
provider account or connection to the author's computer. Stop the local server
with Ctrl+C. No public live-generation endpoint is provided.

## What is genuine, recorded and synthetic?

- Both try-on outputs were generated by the real YouCam Clothes V4 API on
  30 October 2026, from the same unchanged model image and their respective garments.
- The provider ledger records **2 units for A and 2 units for B: 4 units total**. An
  independently recorded 40-unit setup bonus is separate from generation cost.
- Input/output fingerprints, recorded status and sanitized run evidence support
  the comparison. Browsing saved results does not spend processing units.
- The model and unbranded garment inputs were generated with imagegen without
  real-person reference photographs or third-party logos. They are fictional.

The source/provenance view helps distinguish an input, an actual provider output
and a recorded run. It does not turn recorded results into fresh generation or
prove garment fit, sizing, fabric behaviour or purchase outcomes.

## Offline validation

```sh
node --test tools/*.test.mjs
node tools/garment-b-probe.mjs
```

The 39 offline checks cover 18 application checks and 21 B operator guard/portability
checks. They are separate from the two actual provider runs. The second command
is a **dry-run**: it verifies only the fixed model/B assets and provenance. It
reads no key or private execution state, creates no runtime and makes no network
request. The tests use fake transports, never the author's provider account.

## Optional live operator reproduction

Viewing the demo is unlimited and read-only. Fresh generation is a **separate**
operator action. This repository does not provide the author's credential or
permission to spend from their account.

A reproducing operator must independently have authorised YouCam access,
applicable input rights and an allowance/cost boundary. Follow the exact private
approval schema enforced by `tools/garment-b-probe.mjs`; do not copy an offline
fixture as real human approval. The used historical A/B approvals are not an
allowance for another request.

The B tool is fixed to the included model plus rust-shirt hashes, one create,
no automatic retry and at most 12 status polls, 10 seconds apart. Its private state
is fixed to `runtime/garment-b/`; a completed or ambiguous create cannot be reset
to justify another task. `--execute` is explicit; known tasks can use `--resume`.
Result download is separately explicit with `--download-result`.

Any authorised key must be supplied privately as `YOUCAM_API_KEY`, never pasted
into a command line, browser, issue, video or repository. Keep `.env` files,
`runtime/`, approval records, provider identifiers, signed URLs and raw responses
out of source archives and logs. Do not expose the operator tool as a public API.

For judging, the local recorded viewer is usable without provider credentials.
Fresh provider execution needs the judge/operator's own authorised access; no
unrestricted author-funded generation or guaranteed sponsor acceptance of
replay-only testing is claimed. Source/test-build availability is intended to
remain free through 20 November 2026, 16:45 UTC. A public video URL will be added only
after actual recording and verified publication.
